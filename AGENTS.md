# Lingo agent guide

Lingo is a Bun/TypeScript IRC client: React 19 and Vite in the browser, Hono on Bun for HTTP/WebSocket APIs, `irc-framework` for IRC, and SQLite (including FTS5) for persistent history. Read the relevant source before changing behavior; this file is a map, not a replacement for the code.

## Layout

- `src/client/main.tsx` applies stored appearance and mounts the app. `App.tsx` owns session/auth state, network/buffer selection, unread counts and read markers, synced settings, WebSocket catch-up, search/navigation, topic and roster state, which panel fills the main pane, upload capabilities (fetched after sign-in and whenever Settings opens) and file drops on the conversation pane, and the network/channel/user context-menu actions; it renders but does not style the views below. `AuthScreen.tsx` (sign-in, first-run admin setup, server unreachable), `Sidebar.tsx` (brand button that returns from any panel to the conversation, live status, search, networks with collapsible buffer lists, join form, account footer, and `SidebarResizer`; desktop collapse, drawer at ≤640px), `PaneHeader.tsx` (the header every main-pane view uses; `SidebarContext` supplies its "show networks" toggle), `ConversationHeader.tsx` (title with the topic on the same line, inline topic editor, member toggle, actions menu), `Transcript.tsx` (virtualized history plus "jump to latest"; every line, including MOTD blocks and connection markers, is one time/sender/body grid in a single font size and line height with top-aligned cells, sized from the time format, so columns and baselines line up; keep it that way when adding line types, and space rows with padding, never margins, because the virtualizer measures border boxes and a margin overlaps the next row; timestamps show the full date and time on hover; consecutive MOTD lines render as one preformatted block without colors), `MentionComposer.tsx` (the auto-growing message textarea: Enter sends, Shift+Enter adds a line, each non-blank line goes out as its own message, and it stays focused and read-only while sending; mention, slash-command, `/join` channel, and `:shortcode` emoji suggestions, ranked by `sessionRecents.ts`: the in-memory, per-page-load record of whom you mentioned, which channels you joined or talked in, and which emoji you picked, plus who spoke recently; `emoji.ts` detects the `:shortcode` (two or more characters after a space, bracket, or line start), lazy-loads the `gemoji` list as its own chunk, and ranks matches; a `:word` without a matching emoji keeps the menu closed so Enter sends it; it also sends your typing notifications and shows who else is typing, tracked by `typing.ts`; and, when uploads are enabled, the attach button, expiry select, pasted-file uploads, and the one-at-a-time upload queue with progress and Cancel, reachable from App through its `ComposerHandle` ref), `UserList.tsx` (searchable member list grouped by rank; hideable on wide screens, drawer at ≤900px), `ChannelListPanel.tsx`, `SearchPanel.tsx`, `ContextMenu.tsx`, `Dialogs.tsx` (user info, ban list, ignore list, display name, history export), `QuickSwitcher.tsx` (the Ctrl/Cmd+K fuzzy buffer switcher), `ThemePicker.tsx`, and `Icon.tsx` (the inline SVG icon set and `Logo`, the speech-bubble-and-hash mark that `public/favicon.svg` and the PNG app icons repeat) own their respective UI. `settings/` holds `NetworkSettings.tsx` and the tabbed `GlobalSettings.tsx` with one component per tab (`KeyboardSettings.tsx` lists `shortcuts.ts`, the app-wide shortcut table that `App.tsx` implements; `UploadsSettings.tsx` lists and deletes your uploads and is hidden only when uploads are not configured; `UsersSettings.tsx` carries the admin's per-user "Can upload" switch). `chat.ts` holds pure message/buffer helpers (merging pages, joined-channel checks, own names, sidebar order and the buffer stepping/fuzzy scoring used by keyboard navigation, the unread `attention` summary), `syncedSettings.ts` the synced-settings defaults and one-time legacy localStorage migration, `notify.ts` the highlight chime, `tabBadge.ts` the tab title (`(N) Lingo` for unmuted mentions, `• Lingo` for other unread) and the favicon redrawn with a red or grey dot, both fed by `attention()` in `chat.ts` (hidden and muted buffers excluded), `api.ts` the shared fetch/error helpers (`isSessionExpired` for 401s that end the session), `uploads.ts` the XMLHttpRequest upload (fetch reports no upload progress), expiry labels, and byte formatting, and `push.ts` registers `public/sw.js` and subscribes/unsubscribes this device for Web Push. `preferences.ts` holds browser-local preferences (theme, message font family/size, nickname column width, sidebar width/collapsed, member list hidden, display toggles, upload expiry) and `applyAppearance`, which sets `data-theme`, `--mono`, `--font-size`, `--nick-width`, and `--sidebar-width` on `<html>`. `ircFormat.tsx` parses mIRC formatting codes (bold, italic, underline, strike, monospace, reverse, colors) into styled runs over the stripped text and renders them with mention marks and clickable links; the transcript and topic use it, and mention ranges refer to the stripped text. `nickColor.ts` is the single nick-color hash shared by the transcript and roster. Styles live in `src/client/styles/` (imported through `index.css`): `tokens.css` defines every theme variable for dark/light/gruber (components use only those tokens), `base.css` holds controls and shared primitives (`.button`, `.icon-button`, `.badge`, …), and `shell.css`, `conversation.css`, `panels.css`, and `dialogs.css` style their areas. The chrome uses the system sans font; `--mono`/`--font-size` apply to IRC content (messages, composer, nicks).
- `src/shared/contracts.ts` defines API/WebSocket payloads and the network, buffer, message, and channel-state types used by both sides. `src/shared/identity.ts` handles relay/display identities and mention matching. Update both producers and consumers when changing a contract.
- `src/server/index.ts` creates the store, IRC manager, Hono app, WebSocket server, and production static-file serving (fingerprinted `/assets/*` cached as immutable, everything else `no-cache`). `app.ts` contains authenticated routes, Zod input validation, session/origin checks, the security headers and Content-Security-Policy on every response (same-origin only; `img-src` also allows `data:` for the canvas favicon, so keep the client free of inline scripts/styles and third-party hosts), the public `GET /api/health` probe, and event publication. `irc.ts` owns IRC connections, commands, joins, topics, live users/ranks, channel lists, WHOIS/ban-list requests, ignore filtering, and event-to-history translation. `store.ts` owns SQLite migrations, buffers, history, ignores, the persisted disconnected flag, sessions, upload records, and FTS search. `push.ts` owns the VAPID key pair (stored in `server_settings`), the `web-push` sender, and per-buffer push throttling. `export.ts` formats and streams history exports. `uploads.ts` reads the teacup settings, holds `TeacupClient` (upload, delete, cached capabilities), filename cleaning, the offered expiries, and the upload limit arithmetic. `irc-framework.d.ts` declares the subset of the library API this project uses.
- `public/` (copied to `dist/` by Vite) holds `manifest.webmanifest`, the PNG icons, `favicon.svg` (also drawn by `tabBadge.ts` with a cut-out unread dot), and the service worker `sw.js`, which shows pushes and routes notification clicks to `/?buffer=<id>` or an open window.
- `tests/auth.test.ts`, `identity.test.ts`, `migration.test.ts`, `irc.test.ts`, `push.test.ts`, and `uploads.test.ts` cover auth, identity matching, schema migration, IRC/history behavior, Web Push, and teacup uploads (against a fake teacup on `Bun.serve`). `index.html`, `vite.config.ts`, `tsconfig.json`, `package.json`, and `bun.lock` are the app/build configuration. `Dockerfile` (two-stage `oven/bun` build; runs as `bun` with the database at `/data/lingo.sqlite` and a health check on `/api/health`), `compose.yaml`, and `.dockerignore` package it; `README.md` documents running, Docker, reverse proxies, and backups, and `.env.example` lists every setting. Keep them in sync with new runtime settings.
- `docs/roadmap.md` holds planned, not-yet-built feature work (ordered phases with design, files, and tests) and a summary of what is built. Update or remove an item when you implement it.

## Running and checking

- `bun install` installs dependencies. `bun run dev` starts the Bun server with watch mode and Vite; Vite proxies `/api` (including WebSockets) to `127.0.0.1:3000`.
- `bun run build` builds the browser into ignored `dist/` and runs `tsc --noEmit`. `bun test` runs the Bun test suite. `bun run start` serves the built frontend and API from Bun; build first if `dist/` does not exist. `docker compose up -d --build` builds and runs the image (port published on `127.0.0.1:3000`, data in the `lingo-data` volume).
- No password is configured in the environment: on first start, the server prints a one-time setup URL with an in-memory token; open it to create the admin account (`LINGO_PASSWORD` is ignored). Restarting before setup generates a new token. Optional runtime settings: `LINGO_HOST` (default `127.0.0.1`), `LINGO_PORT` (default `3000`), `LINGO_DB_PATH` (default `local/lingo.sqlite`), `LINGO_PUBLIC_ORIGIN` (an exact HTTPS origin when set; also the VAPID subject, and required for push anywhere but localhost because browsers only offer push in secure contexts), `LINGO_TRUST_PROXY=1` (only behind a reverse proxy that appends the trusted right-most `X-Forwarded-For` address), and `LINGO_HISTORY_RETENTION_DAYS` (1–3650; unset keeps history forever unless a user has an override). Uploads to a teacup instance (`../teacup`, which must serve `GET /api/capabilities` with `apiVersion: 1`) turn on with `LINGO_TEACUP_URL` (the address Lingo calls) plus the required `LINGO_TEACUP_USERNAME`/`LINGO_TEACUP_PASSWORD`; `LINGO_TEACUP_PUBLIC_URL` is the base of links posted to IRC (`https:` unless localhost; defaults to `LINGO_TEACUP_URL`), and `LINGO_UPLOAD_MAX_MB` (1–500, default 25) caps each file and sets Bun's `maxRequestBodySize` to that plus 1 MiB. Invalid values stop startup. `.env`, `local/`, `dist/`, and SQLite files are local/generated data; do not overwrite or commit secrets or a user's database. Use a temporary database and a mock IRC peer for end-to-end checks; for uploads, run teacup from a temporary directory holding its `.env` and a copy of `index.html`, with `UPLOAD_DIR` pointing into it.

## Behavioral invariants

- Accounts: exactly one admin (`users.is_admin`, enforced by a partial unique index) plus users the admin creates via `/api/users` (admin-only; list, create, reset password, delete). Until the admin is claimed through public `GET`/`POST /api/setup`, login returns 409. Setup requires the current startup token, removed from the browser URL and compared by SHA-256 digest with `timingSafeEqual`; missing or wrong tokens return 403 without claiming the account. Passwords are salted scrypt hashes; sessions are SHA-256 token hashes tied to `sessions.user_id`. Every network belongs to one user (`networks.user_id`, names unique per user), and buffers, history, ignores, search, away message, browser presence (auto-AWAY), and sessions are scoped to that owner. Routes must check ownership (`ownsNetwork`/`ownedBuffer` in `app.ts`) and answer 404 for other users' ids; `publish` delivers each `ServerEvent` only to its owner's sockets.
- Admin `GET /api/users` returns account summaries with network/session counts and last login; `PATCH /api/users/:id` disables/enables non-admin accounts. Disabling revokes their sessions, closes browser sockets, and disconnects IRC without changing each network's persisted disconnected choice. Disabled users cannot log in (403 only after a correct password) or connect IRC on restart; enabling reconnects only networks not manually disconnected.
- Admin account summaries expose nullable `maxNetworks` and `retentionDays`; `PATCH /api/users/:id` sets these limits (including the admin's own). `POST /api/networks` returns 409 when the user's quota is full. Hourly housekeeping removes messages older than each user's retention cutoff in batches; FTS search loses those messages too. NULL retention uses the global default, NULL network limit means unlimited.
- Password guesses use in-memory 15-minute fixed-window limits: 10 failures per lowercased login name, 30 failures per client IP, 10 setup attempts per IP, and 10 failed password changes per user. Blocked checks return 429 with `Retry-After` before scrypt; successful login clears its username counter. The client IP comes from Bun unless `LINGO_TRUST_PROXY=1` enables the right-most forwarded address.
- `/api/bootstrap` supplies networks, buffers, statuses, per-network ignore lists, synced settings, and server-backed per-buffer unread/mention counts and read markers. `/api/events` pushes typed `ServerEvent`s; the client also fetches message pages and catches up after reconnect. Keep event handling, REST results, and `src/shared/contracts.ts` in sync.
- The persisted `server` buffer is opened by clicking its network heading, not by a duplicate sidebar row. Channel `DELETE /api/buffers/:id` parts the channel **without deleting its history**. Closing a PM in the UI only hides it in synced settings so history survives; the query-buffer DELETE route removes its stored buffer/history and must not be used for that UI action. Hidden buffers and collapsed networks are user-scoped server settings; channel-list tabs and the last-open conversation (reopened on page load) remain browser-local.
- Channel topics and ranked rosters are live IRC state exposed by `GET /api/buffers/:id/channel` and `channel_state` events. A `null` topic is not yet known; `''` means the server reports no topic. Topic edits go through `PATCH /api/buffers/:id/topic` and become authoritative when IRC reports the change. IRC rank symbols come from the server's PREFIX mapping, not a fixed nickname prefix.
- `POST /api/buffers/batch` joins validated distinct channels; `/join` also accepts multiple channel names. `/list` (and "List all channels") fills the network's in-memory channel list, served ranked by user count from `GET /api/networks/:id/channels` and announced with throttled `channel_list` events; the client shows it as a browser-local "channel list" tab. `/join` suggestions read the same list and request one LIST when none is loaded. Slash suggestions in `MentionComposer.tsx` should list only commands supported by `IrcManager.sendText`.
- Ignores are per-network nicks stored server-side; `IrcManager.incoming` drops messages whose sender (or relayed nick) is ignored before they reach history. Disconnect/Connect persists in `networks.disconnected` so restarts and settings edits keep the network offline. "Clear history" deletes a buffer's stored messages (`DELETE /api/buffers/:id/messages`, `history_cleared` event). Muting channels/networks hides unread badges and suppresses notifications, but counts remain available in bootstrap.
- IRCv3 msgids are stored in `messages.msgid`, unique per buffer: `Store.appendUniqueMessage` returns null for a duplicate and `IrcManager.message` then publishes nothing (and no push fires). `echo-message` is requested; when a connection negotiates it, `sendTo` does not record locally and `IrcManager.echoed` stores the server's echo (its time and msgid) as our outbound line, advancing the read marker. Configured connect commands never reach history: their echoes are matched against `Runtime.unrecordedEchoes` and dropped. Without the cap, own lines are recorded locally at send time.
- Chathistory backfill runs when `networks.backfill` (default on; read from the store, so toggling needs no reconnect) is set and the connection negotiated `draft/chathistory` or `chathistory`. Each self-JOIN sends `CHATHISTORY AFTER` from the buffer's newest non-system message (`LATEST` when it has none), continuing a full page after its newest line for at most 5 pages; registration sends `CHATHISTORY TARGETS` from the network's newest stored line and replays each private target the same way. Page size is 200, lowered to the ISUPPORT `CHATHISTORY` limit. Replayed lines (inside a `chathistory` batch) go through `incoming` with `replayed` set: `Store.appendUniqueMessage` also skips an identical `(buffer, time, nick, text)` row, they count as unread and keep their highlight flag, but never push, and their `message` events carry `replayed: true` so the client skips browser notifications and sounds. Replayed own lines are stored via `IrcManager.echoed` (advancing the read marker) even without echo-message, except lines whose text a configured `/msg`/`/notice`/raw PRIVMSG/NOTICE command sent to that target.
- Registration (`IrcManager.onRegistered`) sends NickServ REGAIN if due, then the configured commands, then autojoins: immediately, or after `networks.join_delay_seconds` (0–30, default 0) so services can identify and cloak first. The delayed join reads `autojoin` when it fires and is cancelled on close, redial, and disconnect; explicit joins during the delay go out at once. irc-framework does not rename on ERR_NICKNAMEINUSE, so a taken nick during registration falls back to `nick_`, `nick__`, then numbered variants (at most 10 tries). With `networks.regain_nick` (default off) and a SASL account and password configured, registering under a fallback sends `PRIVMSG NickServ :REGAIN <nick>`; that line never reaches history (live echo suppressed via `unrecordedEchoes`, replays via `configuredLine`).
- A JOIN counts as joined (`Runtime.joined`) from the moment it is sent; a refusal (403, 405, 471, 473–475, 477, 489, 520) for a channel without a confirmed roster removes it again and writes `Cannot join <channel>: <reason>` into the channel buffer, so the next `/join` goes out. A 477 (account required) is retried once per connection, on RPL_LOGGEDIN or after 10 s, if the channel is still autojoined. Other members' joins, parts, quits, kicks, and nick changes are stored as `system` lines with `messages.membership = 1` (`ChatMessage.membership`): never for ignored nicks or replays, never unread (server `getUnread`, client counts, and the "New messages" divider skip them), and shown or hidden by the local "status messages" preference. irc-framework's own 150 s socket idle timeout is disabled on connect because Bun never refreshes it; its PING/PONG timeout detects dead links.
- Keyboard shortcuts live in one `keydown` listener in `App.tsx`; keep `shortcuts.ts` (shown in Settings → Keyboard) in sync. Ctrl/Cmd+F opens search and Ctrl/Cmd+K toggles `QuickSwitcher` (not over a dialog). Esc, when no menu or dialog absorbs it, closes panels and dismisses the conversation's "New messages" divider for the rest of that visit. Alt+↑/↓ steps through the sidebar's visible buffers (`orderedBuffers`/`visibleBuffers`: server buffer first, collapsed networks show only it, hidden buffers never), Alt+Shift+↑/↓ through unread, unmuted, non-hidden buffers (collapsed networks included), only those with mentions while any exist, and Alt+1…9 picks a visible buffer by position, matched on `event.code` because macOS Option+digit types symbols. Alt shortcuts work from the composer or outside text fields and never while a menu, dialog, or the switcher is open. With no query the switcher lists unread buffers (mentions first) then sidebar order; a query also finds closed PMs, which reopen when chosen.
- Typing indicators (IRCv3 `+typing`): `IrcManager.typing` turns another user's TAGMSG into an ephemeral owner-only `typing` event, only for an existing buffer (typing never creates one) and never for ignored nicks, our own nick, or replays. `src/client/typing.ts` holds who is typing per buffer: `active` lasts 6 s and `paused` 30 s without an update; `done`, a message from that nick, or leaving the channel roster clears it. The composer sends only when the synced `sendTyping` (default off) is on: `active` while composing a non-command message and `done` once when the draft is cleared or discarded unsent (never after sending), at most one notification per target every 3 s with a held-back change sent when the window ends. `POST /api/buffers/:id/typing` relays through `IrcManager.sendTyping`, which re-checks the setting, requires a registered connection with `message-tags` whose `CLIENTTAGDENY` allows `typing` (and a joined channel), and drops a repeat of the same state within 2 s.
- `user_settings` stores per-user highlight phrases, mutes, hidden buffers, collapsed networks, `pushIncludesText`, and `sendTyping`. `GET`/`PATCH /api/settings` and bootstrap return them; PATCH validates ownership of every referenced network/buffer id and publishes owner-only `settings` events. The client imports legacy browser values once if no row exists. Appearance, browser-notification permission, and notification sound remain local to the device.
- Read markers are per buffer (`read_markers`), seeded to the latest existing message on upgrade. `PUT /api/buffers/:id/read` accepts an owned message ID, advances the marker only forward, and publishes owner-only `read` events. IRC inbound highlights use shared identity/mention matching and synced phrases; own sent lines advance the marker. A visible buffer at the bottom marks loaded messages as read; other devices reconcile through events and bootstrap.
- Web Push: `push_subscriptions` rows belong to the user and to the session that registered them (`ON DELETE CASCADE`), so logout, revocation, password changes, and expiry stop pushes to that device; the client re-registers an existing browser subscription after sign-in and unsubscribes on sign-out. `POST /api/push/subscriptions` accepts only public `https:` endpoints (no loopback/IP literals), at most 10 per user. `IrcManager.pushNotify` pushes highlighted or inbound private messages only while the owner has no open WebSocket (the presence set) and the buffer/network is unmuted, at most once per buffer every 30 s; the body is the text only when `pushIncludesText` is on. 404/410 from a push service deletes the subscription.
- Search uses SQLite FTS5 in `Store.searchMessages`; its network/buffer and inclusive time filters must also apply to pagination. Relay nickname parsing, display-name overrides, and mention aliases belong to shared identity logic, not ad hoc transcript rewrites.
- History export: `GET /api/buffers/:id/export?format=txt|jsonl` and `GET /api/networks/:id/export` (JSONL only; each line adds `bufferName`, typed `NetworkExportLine`) stream `Store.exportMessages` pages of 1000 in ascending id order with inclusive `since`/`until` millisecond filters, as a `Content-Disposition: attachment` named `<network>[-<buffer>]-<yyyy-mm-dd>.<ext>` in sanitised ASCII. Plain text strips mIRC formatting; JSONL keeps stored text verbatim. The client downloads through a plain link from `ExportDialog`, so the browser streams the file.
- Uploads: Lingo never fetches or renders uploaded content; the client inserts the returned link at the caret and never sends it. Browsers never talk to teacup: `POST /api/uploads` (multipart `file` + `expiry`) checks, in order, the feature (404 when unconfigured), `users.can_upload` (403; migration grants it to the admin, the admin toggles it with `PATCH /api/users/:id { canUpload }`), teacup availability (502), `Content-Length` (411 missing, 413 before the body is read), exactly one non-empty file and an offered expiry (400), file size (413), then the limits (429 with `Retry-After`: 30 uploads per hour and 500 MiB per day per user, counted from `uploads` rows, including deleted ones, plus uploads still in flight). It sends the cleaned filename (`[A-Za-z0-9._-]`, ≤100 characters, always a short alphanumeric extension) with explicit `ttl_seconds` or `permanent=true` using Basic auth, verifies teacup returned exactly one file with a well-formed id and path, and records the link rebuilt on `LINGO_TEACUP_PUBLIC_URL`. teacup's per-file rejections become 422 with its message; every other failure is 502 without credentials or teacup's address. `GET /api/uploads/capabilities` always answers 200 (`enabled: false` with `not_configured`/`not_permitted`/`unavailable`); offered expiries are the `1h`/`1d`/`7d`/`30d` presets within teacup's `maxTtlSeconds` plus `permanent` when allowed, `maxBytes` is the smaller limit, and teacup's capabilities are cached for its `max-age` (60–600 s) and dropped after a failed upload. `DELETE /api/uploads/:id` (owner only) deletes from teacup (a teacup 404 counts as done) before marking the row deleted; deleting a user first removes their live files from teacup. Hourly housekeeping drops deleted or expired rows older than a day.
- Preserve migrations and existing messages when changing storage. Keep input validation and same-origin/session protection on new API routes. For UI changes, run the build/typecheck and exercise the actual browser surface; for IRC protocol changes, exercise a mock peer as well as `bun test`.
